# Frontend — KURASHI

`hono-api` の EC API に接続する日本語の React SPA です。
React / TypeScript / Vite / React Router / TanStack Query を使用しています。
React スキルの方針に沿って、取得データのキャッシュ・重複排除、ページ単位の遅延読み込み、
検索入力の遅延反映、派生データの直接計算を使用しています。

## 起動

Node.js 24 と pnpm 10.24.0 を使用します。リポジトリ直下から実行してください。

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

http://localhost:5173 を開きます。別ターミナルで [hono-api](../hono-api/README.md) の手順に従って
API と DB を起動し、マイグレーションと `JWT_SECRET` の設定を済ませてください。
既存 API のソースや DB スキーマの変更は不要です。

Vite は `/api/*` を `http://localhost:8787/*` に転送します。
別の転送先を使う場合は `.env.example` を `.env` にコピーし、`API_PROXY_TARGET` を変更してください。
`VITE_` 変数はブラウザーに公開されるため、シークレットを設定しないでください。

## 対応機能

- 商品一覧・商品名/SKU検索・価格順/新着順・在庫フィルター・ページ送り
- 商品詳細・数量指定・バッグ・複数商品の注文
- 会員登録（登録後にログイン）・ログイン・本人確認・ログアウト
- お気に入り登録/解除/一覧
- 本人の注文一覧・詳細・明細全体の置換・取消
- 自分が登録した商品の作成・編集・在庫更新・削除
- 読み込み・空データ・APIエラー・認証期限切れ・モバイル表示

API のフィールド、HTTP メソッド、所有権、数量・価格の上限は [API仕様](../hono-api/docs/API.md) に合わせています。
削除・取消操作は確認ダイアログを表示します。
商品画像の API はないため、カードは商品名の先頭文字を使った装飾です。
決済・配送は既存 API の範囲外です。

## 状態と認証

Bearer トークンのみを `sessionStorage` の `kurashi.session.v1` に保存し、起動時に `/auth/me` で検証します。
パスワードは保存しません。認証付き API が401を返すとトークン・ユーザー別キャッシュ・バッグを破棄します。
ブラウザーの保存領域が無効な場合はメモリーでのみ保持します。
バッグはメモリーで管理し、再読み込み・ログアウト時にリセットします。ログイン後はバッグを維持します。
バッグの数量は最新取得済み在庫の範囲に制限し、確定時の価格・在庫・所有権は API が判定します。
注文変更では元の注文数量が返却されるため、現在在庫だけで入力を制限せず API の確定結果を表示します。

一覧 API に総件数・検索・所有者フィルターがないため、100件ずつ全件取得した後で検索・ページ表示します。
大量データでは API に検索・総件数・所有者フィルターを追加してサーバー側でページ処理する必要があります。
並行更新中の offset ページングは API の仕様上スナップショットを保証しません。

## 検証

```sh
pnpm check       # 型チェック、APIクライアント・画面操作テスト、本番ビルド
pnpm test
pnpm build
pnpm preview    # ローカルで本番成果物を確認（APIプロキシあり）
```

テストは HTTP をモックし、実 DB には書き込みません。
実 API では、登録 → ログイン → 商品登録 → 商品詳細 → バッグ → 注文 → 注文変更/取消 → お気に入り → 商品編集/削除の順に確認できます。

## 本番配信

`pnpm build` の成果物は `dist/` です。`dist/` を静的ホスティングし、同一オリジンの `/api/*` を
Hono API の `/*` にリバースプロキシしてください。Vite の proxy は開発・ローカルプレビュー専用です。
ルーティングはハッシュ方式のため、画面 URL のリロード用 rewrite は不要です。
別オリジンの API を使用する場合はビルド時に `VITE_API_BASE_URL` を指定し、API 側に配信元を許可する CORS 設定を追加してください。
